# Decision Log

This file is the project's single source of truth for "why". Every non-trivial
implementation decision - one a competent engineer could reasonably have decided
differently - is one row of the table below.

Contract for this file:

- No rationale is recorded anywhere else. Source files, manifests, build files
  and workflows carry only labels, mechanical constraints and `DL-####`
  pointers; the reasoning behind a marker is read here.
- Every `DL-####` marker that appears anywhere in the repository outside
  `original/` resolves to a row here. A marker with no row is a dangling
  reference and a defect.
- Rows are append-only. An identifier is never reused, renumbered or deleted.
  A decision that is later replaced keeps its row and is referenced by the row
  that replaces it.
- The vendored tree `original/` is upstream curl and carries no marker of this
  project's.

Column meanings: **Decision** is what was chosen. **Alternatives considered**
are the options rejected. **Why this choice** is the reasoning. **Risks** are
what the choice costs or exposes.

## Decisions

| ID | Decision | Alternatives considered | Why this choice | Risks |
|---|---|---|---|---|
| DL-0001 | Import the vendored baseline from upstream tag `curl-8_21_0` (8.21.0, tagged 2026-06-24) in full, then treat `original/` as immutable. | Freeze the in-repo `8.19.0-DEV` snapshot that was at repository root; import a subset of the tag; track an upstream branch instead of a tag. | The requirements pin the oracle to the newest stable release at import. The in-repo snapshot declared `LIBCURL_VERSION "8.19.0-DEV"`, which is a development snapshot rather than a release tag and is behind 8.21.0, so it cannot serve as the oracle. A full import is what makes every enumeration - options, error codes, protocols, CLI flags, test expectations - derivable mechanically instead of from memory. | The tag must not be bumped after the import commit, so an upstream security fix needs an explicitly authorised rebase task. Baseline integrity depends on the recursive checksum of the tree matching the recorded value, so any edit under `original/` - including a well-intentioned one - fails the immutability gate. |
| DL-0002 | Introduce `curl-rt` as a leaf runtime facade that owns the async runtime and performs `block_on` at exactly one call-stack level, and express the runtime ban as a ban with a wrapper exemption naming that crate. | Hand-write HTTP/2, HTTP/3 and QUIC with no async dependency; allow `tokio` directly in `curl-core`; drop HTTP/2 and HTTP/3. | Every mandated HTTP/2, HTTP/3 and QUIC crate depends on `tokio`, so a literally transitive ban on async runtimes is unsatisfiable for the prescribed topology. The no-internal-runtime rule's own scope clause permits a facade owned by the core, so the facade must exist and must be named for the ban to be checkable. | The facade is the only sanctioned sync-to-async crossing; widening its surface lets async leak into the core and breaks the externally-driven `curl_multi_socket_action` contract. A nested runtime created from an application callback panics, so the single `block_on` site must stay single. |
| DL-0003 | Introduce `curl-types` as a leaf crate holding the types, data structures and format/parse helpers shared across crates. | Duplicate shared types in each crate that needs them; let subsystem and protocol crates depend on `curl-core`. | The dependency-direction rule forbids a protocol or subsystem crate from depending on the core, and its scope clause requires shared types to live in a leaf crate depended on by both sides. | A shared leaf accretes unrelated types and can drift into a second core; each addition is reviewed against "is this genuinely shared". |
| DL-0004 | Introduce `curl-pingpong` as a leaf crate for the shared line-protocol state machine. | Place the state machine in `curl-core`; duplicate it in the FTP, SMTP, IMAP and POP3 crates. | `lib/pingpong.c` is shared by FTP and the three mail protocols. Placing it in the core would need an upward edge from four protocol crates, which the dependency-direction rule forbids; duplicating it four ways would violate pattern-class completeness, because a defect fixed in one copy would silently survive in three. | Protocol-specific behaviour must stay in the protocol crates rather than accumulating as flags in the shared machine. |
| DL-0005 | Cover the baseline protocols the requirements' own enumeration omits, taking the oracle rather than the enumeration as authority. SCP and SFTP (`CURLPROTO_SCP`, `CURLPROTO_SFTP`) are live baseline capabilities and get `curl-proto-ssh`. The RTMP family (`CURLPROTO_RTMP`, `RTMPT`, `RTMPE`, `RTMPTE`, `RTMPS`, `RTMPTS`) is deprecated and no longer implemented at the pinned tag, so what it needs is constant and symbol preservation, not a protocol port. | Follow the requirements' enumeration literally and drop SCP/SFTP; treat the surviving RTMP constants as a live protocol and port an implementation for them; delete the RTMP constants because nothing implements them. | SCP/SFTP are present and selectable at the pinned tag - `original/lib/vssh/{libssh.c,libssh2.c,vssh.c}`, `original/CMake/Find{Libssh,Libssh2}.cmake`, and the `--with-libssh2` / `--with-libssh` flags in `original/configure.ac` - and dropping a baseline protocol is prohibited while provenance must account for every translation unit. RTMP is the opposite case, and only the oracle shows it: `original/docs/libcurl/symbols-in-versions:977-982` records all six `CURLPROTO_RTMP*` names as deprecated in 8.20.0, the implementation and the librtmp flag are gone from the pinned tag (no `lib/*rtmp*`, no `CMake/FindLibrtmp.cmake`, no librtmp option in `configure.ac` or `CMakeLists.txt`, no CLI reference), yet `original/include/curl/curl.h:1097-1102` still defines all six constants and `original/lib/version.c:574` still holds the rtmp-version slot in `curl_version_info_data`, reporting NULL. Preserving obsolete discriminants and struct slots is required; resurrecting a protocol the baseline no longer implements would be adding capability beyond the baseline, which is prohibited. MQTT and MQTTS are both live: `original/lib/mqtt.c:985` defines `Curl_protocol_mqtts` and the build reports MQTTS whenever a TLS backend is enabled (`original/CMakeLists.txt:2027`), while the public bitmask has only `CURLPROTO_MQTT` and no MQTTS bit, so the MQTT crate carries both schemes over `curl-tls` and no new protocol constant may be added. The "Support MQTTS" entry in `original/docs/TODO.md` is a stale upstream note, not the capability's status. | The SSH adapters rest on retained C libraries, so they hold unsafe-allowlist entries and their availability depends on system packages. The RTMP finding contradicts the plan's premise for `refactor/curl-proto-rtmp` and `refactor/curl-rtmp-librtmp`, which the plan justifies by a baseline implementation that the pinned tag does not have: whoever writes those members must reconcile them against the oracle first, keeping the constants and their deprecation semantics without porting a removed protocol. The planned-member inventory is a frozen recorded value and is not edited here. |
| DL-0006 | Extend internal-surface equivalence treatment to the tool-unit test directory (`original/tests/tunit/`) as well as the library unit directory (`original/tests/unit/`), and take the mapping denominator to be the union of both, enumerated mechanically from the pinned tag's own build-include files rather than from any recorded figure. | Cover only the single internal-linkage directory the requirements name. | The tool-unit directory has the structurally identical problem - it links against functions that are internal to the tool - and its own README says it exists because those functions live outside the library. Covering only the named directory leaves its cases unaccounted for, with no skip reason and no Rust counterpart. | A documented deviation from the literal wording: every gate, generator and report must use the union, or the mapping-completeness check silently passes on an incomplete set. The case count moves between upstream releases, so any figure written down instead of derived goes stale - at the pinned tag the two directories hold more cases than the plan's indicative figures. |
| DL-0007 | Implement the 15 variadic and `va_list` public symbols in a first-party C thunk at `refactor/curl-abi/csrc/varargs.c`, compiled by the ABI crate's build script, forwarding to non-variadic Rust entry points. Build with the pinned stable toolchain only. | The nightly `c_variadic` feature gate; declare the symbols non-variadic and rely on calling-convention coincidence; expose only the `va_list` forms and drop the variadic ones. | Rust cannot define C-variadic functions on stable, verified by compilation, and the nightly argument-extraction API is still in flux. The four target ABIs use four incompatible `va_list` representations, and on Apple AArch64 variadic arguments pass on the stack while non-variadic integer arguments pass in registers, so the non-variadic declaration is unsound on a platform in the matrix. Delegating extraction to the platform C compiler is correct by construction on all four. | Adds a non-Rust unsafe surface that must appear on the unsafe allowlist and be counted with per-site justification in the unsafe audit, and makes a C toolchain a hard build prerequisite. `va_list` verification on macOS AArch64 and Windows MSVC is recorded as deferred, never as passed. |
| DL-0008 | Catch unwinding at every ABI entry point and translate a caught panic into the baseline error code that call returns; abort only where the entry point has no error channel. | `panic = "abort"` for the whole shared library, as a published Rust drop-in replacement for a C compression library does. | Unwinding across a non-`-unwind` ABI boundary is undefined behaviour, so the panic must not escape. libcurl's contract is that a failing call returns a `CURLcode` rather than killing the host process, and aborting a long-running application because of an internal library error would be a behavioural regression no error code can express. | A caught panic can leave internal state partially updated, so the barrier must not become a way to ignore logic errors; caught panics are traced. `panic = "abort"` must never appear in any profile, which the profile tables enforce. |
| DL-0009 | Pin `ring` as the single crypto provider by disabling default features on `rustls` and `quinn`, and disable default features on any dependency whose defaults would reintroduce a second TLS or crypto stack (`ldap3`'s `tls-native`, `metrics-exporter-prometheus`'s `push-gateway`). | Accept the default feature sets of the coupled release set; keep `aws-lc-rs` as rustls's provider; allow `native-tls` for LDAPS. | With default features the coupled set links two C/assembly crypto stacks at once - `aws-lc-rs` with `aws-lc-sys` plus `ring` reached from `quinn-proto`, `rustls-webpki` and `rustls-platform-verifier`. `aws-lc-sys` needs cmake and, on Windows, an assembler, and is the commonest cross-compilation failure point, while Windows MSVC x86-64 and macOS AArch64 must compile and link. A probe resolution of the coupled set measured 123 packages with default features against 89 with a single provider pinned - 34 fewer, `aws-lc-rs` and `aws-lc-sys` gone, exactly one rustls in both cases. `ldap3`'s `tls-native` pulls `native-tls` into every LDAP-enabled build, and `push-gateway` reaches rustls with default features through `hyper-rustls`, reinstating `aws-lc-rs` under workspace-wide feature unification; LDAPS is carried by `curl-tls` instead. | `ring`'s platform support bounds the platform matrix. The provider is a recorded value, so changing it later is not an append and needs an authorised amendment. Any new dependency must be checked for a default that reintroduces a banned transitive. |
| DL-0010 | Implement the duplicate-dependency gate as "exactly one distinct `rustls` version in `Cargo.lock`", equivalently "no top-level entry of the duplicates report is named `rustls`". | `cargo tree --duplicates` produces no output; grep the duplicates report's raw output for the string `rustls`. | In the single-provider configuration the only duplicated packages are `getrandom` and `syn`, both introduced by third parties and outside this project's control, so the no-output form fails an otherwise fully compliant graph. Grepping raw output yields false positives because `rustls` appears as a child line inside other packages' inverted trees. | The gate is narrower than a general duplicate ban: other duplicated crates are reported but do not fail the build, so duplication elsewhere must be watched by review rather than by the gate. |
| DL-0011 | Make the unsafe allowlist crate-level: every unsafe FFI adapter is its own leaf crate named on the written allowlist, and every other crate root declares `#![forbid(unsafe_code)]`. Workspace lints set `unsafe_code` to `deny` so allowlisted roots opt out explicitly with `#![allow(unsafe_code)]`. | A module-level allowlist inside the subsystem crates, as the rule's text suggests; set the workspace lint to `forbid`. | `#![forbid(unsafe_code)]` is strictly stronger than `deny` and cannot be locally overridden - an inner allow for the same lint is itself an error - so a crate hosting one FFI module cannot carry the attribute. Splitting each adapter into its own crate satisfies both halves of the rule literally and is stronger than a module allowlist, because the allowlist becomes a short list of crate names CI checks by reading crate roots. A workspace-level `forbid` would make the allowlisted roots impossible to express. | More crates in the graph and more manifests to keep in step. The allowlist and the crate roots are two representations of one fact and must be checked against each other. |
| DL-0012 | Prefer an existing safe high-level wrapper crate over a raw `-sys` crate wherever one exists at adequate maturity. | Use raw `-sys` bindings uniformly for every retained C library. | The OpenSSL, mbedTLS, Schannel, Secure Transport, c-ares, GSSAPI and wolfSSL wrappers are safe, so their adapters need no `unsafe` at all and their parent crates keep `forbid`. Applying the preference removes seven adapters from the unsafe allowlist entirely. | A wrapper can lag its C library or omit an API curl uses, so each is checked against curl's actual usage before adoption, and a wrapper that falls short sends its adapter back to hand-written bindings. |
| DL-0013 | Hand-write FFI bindings, in dedicated allowlisted crates, for GnuTLS, librtmp, libidn2, Windows IDN, Apple IDN, libpsl and OpenLDAP/lber. Generate the skeletons with `bindgen`, commit the output, and never run `bindgen` at build time. | Depend on `-sys` crates for these libraries; adopt `gnutls-sys 0.1.2` / `gnutls 0.1.3`; adopt the unmaintained `openldap 1.2.2`. | Four of these `-sys` crates do not exist on crates.io at all, and the GnuTLS crates are at 0.1.x with coverage far below curl's usage - session handling, certificate verification, ALPN, session resumption and TLS-SRP. Committing generated bindings keeps the build reproducible and offline, and keeps `libclang` off the list of build-time requirements for consumers. | Committed bindings must be regenerated when the system C headers move, and a mismatch is a runtime hazard rather than a compile error, so each adapter checks the library version it was generated against. |
| DL-0014 | Keep `lib/memdebug.c` in provenance scope and build the Rust analog: a debug-only, counter-driven allocation-failure injection facility with leak accounting, gated by a Cargo feature the shim maps from the baseline's own debug flag. | Declare the unit not ported, as the superseded prior attempt did. | Torture mode is a required threshold row, and torture mode works by failing the *n*th allocation inside a debug build and asserting the library unwinds cleanly - exactly what that unit implements. Declaring it unported forfeits a required row rather than deferring it. | The accounting output must be in the form the upstream suite's memory-analysis module already parses, and that module is inside the immutable tree and cannot be adapted, so the output format is fixed by something this project cannot change. |
| DL-0015 | Route all allocation through a curl-owned indirection in the allowlisted `curl-alloc` crate, which also hosts the failure injection. | `#[global_allocator]`; call the Rust allocator directly and ignore the hook. | `curl_global_init_mem` installs application-supplied malloc, free, realloc, strdup and calloc functions at runtime; a global allocator is chosen at compile time and cannot honour that contract. Hosting injection in the same crate keeps one path through which every allocation passes. | Any allocation that bypasses the indirection silently ignores the application's hook, which is invisible in normal runs and only shows up in torture mode or in an application that relies on the hook. |
| DL-0016 | Classify every baseline configure flag and CMake option into five mapping classes - capability, backend-selection, value-or-path, test-infrastructure, accepted-and-inert - and give only the first two a Cargo feature. | Map every flag to exactly one Cargo feature with identical enable/disable semantics, as the requirements literally state. | The literal rule is unsatisfiable for three families: value-carrying flags such as the GSSAPI include and library paths and the default TLS backend selector; test-infrastructure flags naming external servers; and build-mechanics flags with no Rust semantics, such as unity builds (Cargo already compiles a crate as one unit) and the typecheck layer (a header-only layer that is an immutable input). | A documented deviation for three of five classes. `curl_version_info` output must still reflect the enabled capability set accurately for every class, so the inert classes need their own assertions rather than being forgotten. |
| DL-0017 | Preserve seven independent share lock domains, each dispatching to the application's lock and unlock callbacks with the baseline's own partition enumeration value and access mode. | One coarse mutex over the whole share object; internal locks that do not call out to the application. | The baseline already partitions shared state into seven independently lockable classes and exposes the partition identity to the application. Collapsing them fails the concurrency gate, which rejects a single coarse lock over independent partitions, and changes observable behaviour, because the application's callback would stop receiving the correct partition and mode. | Seven domains mean seven lock-ordering obligations; the order and the contention hotspots are recorded in the concurrency analysis, and internal locking must not change observable reentrancy. |
| DL-0018 | Implement HTTP/1.x parsing and date parsing first-party. | `httparse` for HTTP/1; `chrono` or `time` for `curl_getdate`. | Compatibility is bug-for-bug: `httparse`'s strictness and error taxonomy differ from the baseline's HTTP/1 and chunked decoders, and neither date crate reproduces the baseline's accepted-format set and quirks. The HTTP-response corpus deliberately includes malformed and truncated inputs, so every difference would surface as a divergence rather than staying hidden. | More first-party parser code to keep correct; the fuzz targets over the URL, response, chunked, header, cookie, netrc, FTP-response and Telnet surfaces exist to carry that weight. |
| DL-0019 | Retain libssh2 and libssh adapters for SCP and SFTP, as raw-binding allowlisted crates. | A pure-Rust SSH stack such as the `russh` family. | The baseline's flags name libssh2 and libssh, so retaining them keeps the flag identity and mirrors the mandated TLS-adapter pattern. Substituting a Rust SSH stack would add a second wire-behaviour substitution, each of which owes a full boundary-difference enumeration under the dependency-substitution gate. | Two crates stay on the unsafe allowlist, and SCP/SFTP availability depends on system libraries at build time. |
| DL-0020 | Relocate the prior attempt's documentation to `refactor/docs/history/` with a superseded header, and keep this project's CI in the root `.github/` dot-directory while upstream's `.github/` and `.circleci/` move inside the vendored tree. | Place the prior-attempt documentation under `original/`; delete it; keep a project documentation directory at root; put project CI somewhere other than `.github/`. | Anything added under the vendored tree changes its recursive checksum and breaks both the baseline-integrity criterion and the immutability gate, so the history cannot live there. Additional non-dot root directories are prohibited, so it lives under the Rust tree. No CI provider reads workflow configuration from anywhere but `.github/workflows`, and the requirements simultaneously demand CI gates, so dot-prefixed tooling directories at root are treated as root-level files for the three-directory constraint. | Root `.github/` is project-owned by convention rather than by a mechanical check, so an upstream workflow left there is a real hazard - it is what made CI ownership ambiguous once already. The documentation site must exclude the vendored tree, or discovery ingests roughly a thousand upstream files. |
| DL-0021 | Record every `abidiff` suppression as a divergence-allowlist entry carrying a written rationale and a named owner, and build both trees with full DWARF in the same CI run (the `abi` profile exists for that). | Silent tool configuration; suppress by default and review later; skip the ABI diff when it is noisy. | `abidiff` compares debug information, and Rust-emitted debug information names types differently from C, so spurious differences are expected rather than exceptional. A reviewed suppression list keeps a real ABI break from hiding among the noise, which silent configuration cannot do. | Both trees must be rebuilt with debug info on every run, which costs CI time, and a growing suppression list is itself the signal that the rewrite is drifting. |
| DL-0022 | Host every network-exposed observability surface - the metrics endpoint and the health and readiness checks - in the verification tree, and keep implementation-tree instrumentation unconditional but inert without a subscriber. | Add flags or endpoints to the tool or the library; feature-gate the instrumentation; skip the observability rule as inapplicable to a transfer tool. | The Observability rule requires a metrics endpoint, health and readiness checks and a dashboard template, while the requirements prohibit new CLI flags and library options and require byte-identical stdout, stderr and written output across four corpora. The harness runners are the only long-running processes in this system for which such endpoints are meaningful; a transfer tool is not a service. Inert instrumentation delivers structured tracing with the existing correlation identifiers and changes not one byte of output. | Instrumentation that nothing exercises rots, so the local observability check installs a subscriber, drives a real transfer and asserts the expected spans and metric series appear. |
| DL-0023 | Treat every mandated inline annotation - truncation justifications on surviving narrowing casts, reserved-field markers, lint-allow attributes, per-site unsafe justifications - as a machine-checked gate marker carrying a `DL-####` pointer rather than as prose. | Embed the rationale in code and configuration comments where the gate looks for it; drop the annotations and keep only the log. | The requirements mandate those inline annotations while the Explainability rule forbids rationale in code comments. A short marker plus a pointer satisfies both: CI still finds its marker, and the reasoning stays in one reviewable place instead of drifting between comment and log. | A marker whose row is missing is a dangling reference, so every referenced identifier must resolve to a row here - the contract stated at the top of this file. |
| DL-0024 | Interpret "distributed tracing across service boundaries" as this system's three real boundaries - the sync-to-async crossing inside the runtime facade, the ABI-to-core-to-protocol-crate crossings, and the CI verification pipeline stages - and implement no outbound trace-context header injection. | Inject trace-context headers into outgoing requests; declare distributed tracing inapplicable and implement nothing. | curl has no service boundaries of its own, and injecting headers would alter the wire and break the differential byte comparison outright. The rule's intent is that work crossing a boundary be traceable end to end, and those three are the boundaries that exist. | A documented deviation from a literal reading of the rule; anyone expecting W3C trace-context propagation on the wire will not find it. |
| DL-0025 | Let the Agent Action Plan supersede the stale sections of the in-repository technical specification, and adopt edition 2024, Cargo resolver 3 and the pinned latest-stable toolchain (1.97.1) as the recorded MSRV, enforced by a dedicated CI job. | Implement the design those sections describe: a fixed three-crate workspace, cbindgen as a header generator, rustls-only TLS, a hyper-based HTTP stack, edition 2021 with MSRV 1.75, Windows excluded, and a coverage-percentage completion gate. | Those sections describe the superseded prior attempt, whose own failure modes the current requirements are engineered to prevent; thirteen systematic divergences are tabulated in the plan. The current requirements mandate edition 2024 (floor 1.85), the latest stable toolchain and an MSRV enforced mechanically rather than declared. | An agent reading the stale sections without the precedence statement implements the wrong architecture, which is why the prior artifacts carry a superseded header (DL-0020). A single recorded MSRV must stay equal in three places - the toolchain channel, `rust-version` and the workspace metadata - or the MSRV job checks a version nothing else uses. |
| DL-0026 | Declare the five build configurations, the `default` forward-contract feature set and the planned member inventory under `[workspace.metadata.curl]` in the virtual root manifest, with the default set derived mechanically from `original/configure.ac`. | A `[features]` table in the root manifest; a placeholder root package created solely to host features; a separate hand-maintained configuration file; enumerate the default feature set from memory or from prior documentation. | The root manifest is a virtual manifest, and Cargo rejects a `[features]` table in one, so the contract needs a home Cargo will carry without altering resolution. The root Makefile, the build shim and the CI workflows all need one authoritative machine-readable source for the five frozen configuration names and the frozen default set; `[workspace.metadata]` is that home and Cargo ignores it. Deriving the default set from the baseline's own configure script is what makes it a mechanical fact rather than a recollection - and it is what puts MQTT in the set while leaving SCP and SFTP out: with no arguments the baseline compiles MQTT in, because `CURL_DISABLE_MQTT` is defined only by `--disable-mqtt` (`original/configure.ac:1114-1128`, `:5392`), while the SSH backends stay off, because they are selected by explicit `--with-libssh2` and `--with-libssh` flags whose own default is off (`original/configure.ac:2404-2409`). The RTMP family is absent from the set for a different reason, recorded in DL-0005. | Cargo does not validate `[workspace.metadata]`, so the configuration names, the default set and the planned inventory are only as correct as the CI checks that read them; a typo there is silent until a gate reads it. The values are frozen at import, so they are append-only. |
| DL-0027 | Make `testing/fuzz` a workspace member rather than a `Cargo.toml` `exclude` entry. | Exclude it, as cargo-fuzz scaffolding conventionally is; place fuzz targets beside the code they exercise. | The verification-tree separation rule keeps every fuzz target out of the implementation tree, and the tree must resolve and compile under the pinned stable toolchain for the corpus-replay gate to mean anything. Membership is what makes that mechanically checked on every ordinary build rather than only when someone runs the fuzzer. | The fuzz members' dependencies join workspace-wide feature unification, so a fuzz-only dependency can reintroduce a banned transitive; the resolved-invariants checks are what catch that. |
| DL-0028 | Depend on `gsasl-sys` with default features disabled. | Default features, which enable `build_bindgen`; a different GSASL binding crate; hand-written GSASL bindings. | `build_bindgen` runs `bindgen` against the system headers at build time and fails on current glibc, which would break every build with the GSASL adapter enabled. The crate's pre-generated bindings are used instead, consistent with the decision to commit generated bindings (DL-0013). | The pre-generated bindings must match the system GSASL version, so the adapter checks the runtime version rather than assuming agreement. |
| DL-0029 | Pin the MIRI toolchain as machine-read marker comments (`MIRI-TOOLCHAIN`, `MIRI-COMPONENTS`) in `rust-toolchain.toml` and select it explicitly as `cargo +$MIRI_TOOLCHAIN miri`. Install it in two commands: `rustup toolchain install <pin> --profile minimal`, then `rustup component add --toolchain <pin> miri rust-src`. | A second `[toolchain]` table for nightly; `channel = "nightly"` for the whole build; leave the MIRI toolchain unpinned and take whatever nightly is installed. | MIRI is nightly-only while the build toolchain is the pinned stable channel, and the ABI round-trip suite must run under MIRI, so two toolchains are required rather than one. rustup accepts exactly one `[toolchain]` table, so the nightly pin cannot be a second table; a marker comment keeps it pinned, greppable and in the same file as the stable pin. | A dated nightly can disappear from the mirrors, and a single combined install command fails, so the two-command sequence is part of the decision rather than an incidental detail. Because the pin lives in a comment, no tool validates it: a typo surfaces only when the MIRI job runs. |
| DL-0030 | Declare the `default` feature set as the baseline's capability defaults **with a TLS backend selected**, and record the baseline's own TLS-selection behaviour, its two oracle locators and the project default as structured metadata under `workspace.metadata.curl.default-features.tls-selection`, rather than describing the set as the mechanical equivalent of `./configure` with no arguments. | Describe the set as equivalent to a no-argument `./configure` run and keep `rustls` in it; ship no default TLS backend so that a no-argument build reproduces the baseline's abort; drop `rustls` from the default set and select one of the C backends instead. | Literal equivalence is unsatisfiable against the oracle: `original/configure.ac:299` sets `OPT_RUSTLS=no`, and `original/configure.ac:519-523` aborts with "select TLS backend(s) or disable TLS with --without-ssl." when no TLS choice has been made, so a no-argument run yields no capability set at all - it fails. The requirements separately mandate rustls as the default backend, so the two statements conflict and only a recorded deviation reconciles them. Holding the baseline behaviour, both locators and the project default as data rather than prose keeps the forward contract checkable against the pinned tag. | The `default` set is frozen at import and never renamed or extended, so the deviation is permanent unless an authorised amendment changes it; a reader who takes the contract as literal no-argument-configure parity will expect a TLS-less default. No capability moved: the feature list itself is unchanged. |
| DL-0031 | Add `testing/audit` as the workspace's first member as soon as any root manifest exists, and treat a non-empty `[workspace].members` list as a checked contract rather than a convention. Membership stays the sole mechanism that carries the lints, the pins and every cargo-graph gate, and each crate is appended by the operation that creates its manifest. | Keep `members = []` until the first implementation crate lands; make the root manifest a package so it can hold dependencies; declare members with a glob so no list has to be maintained. | An empty member list is not a neutral starting state: with `members = []` cargo 1.97.1 refuses to run at all - `cargo metadata`, `cargo tree` and `cargo build` each fail with "contains no package: The manifest is virtual, and the workspace has no members" - so the workspace cannot be built, tested, linted or resolved, and `Cargo.lock` cannot be generated. Every gate that reads the resolved graph therefore checks nothing. `testing/audit` is already in the frozen planned-member inventory, it is where the generated audits belong, and it depends only on crates already pinned, so it makes the workspace operable without anticipating any implementation decision.
